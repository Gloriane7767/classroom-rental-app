## 🌿 Git Workflow Requirements

Your repository must demonstrate proper Git usage.

### Required Git Practices

- Use **frequent, small commits**
- Write **clear commit messages** describing:
    - what you changed
    - why you changed it
- Create at least **one separate branch**
- Merge your branch back to `main` when the feature is complete

---

## 🧹 Code Quality Expectations

- Use meaningful class, method, and variable names
- Apply OOP principles correctly
- Keep classes focused on a single responsibility
- Handle errors using exceptions where appropriate

## 📋 Submission & Evaluation Guide

To ensure a smooth evaluation, use this checklist to prepare for your project submission and one-to-one meeting.

### 🏁 Submission Checklist

Before your meeting, ensure your **new Git repository** includes:

- [ ] **Functional Requirements:** All core features from your chosen project are implemented and working.
- [ ] **OOP Principles:** Correct use of encapsulation, inheritance/interfaces, and polymorphism.
- [ ] **Data Persistence:** SQL + JDBC is fully integrated to save and load data.
- [ ] **Collections & Streams:** Used for searching, filtering, or sorting data.
- [ ] **Error Handling:** Use of exceptions to handle invalid inputs or database issues.
- [ ] **Documentation:** A `README.md` with setup instructions and a **UML Class Diagram**.
- [ ] **Git Workflow:** Frequent, small commits and at least one merged feature branch.

### 🤝 One-to-One Meeting Presentation

Be prepared to present your work in roughly 10–15 minutes:

1.  **The Big Picture (2-3 mins):** Briefly explain your choice of project and show your UML diagram.
2.  **Live Demo (5 mins):** Demonstrate the "Happy Path" (working features) and how the system handles errors. Show the data in your database.
3.  **Code Walkthrough (5 mins):** Highlight a piece of code you are proud of (e.g., a complex query or logic) and explain *why* you built it that way.
4.  **Q&A:** Be ready to discuss potential improvements or technical challenges you faced.

> **Pro Tip:** Keep the IDE and database tool ready before the meeting.
